# LOOTY 商品別損益レポート

## データの正（真実の優先順位）
- **売上 = Shopify** の `net_sales`（値引き・返品控除後）。Metaの計上売上（コンバージョン値）は判断に使わない（下記「突合」参照）
- **広告費 = Meta**（Supermetrics FA, アカウント `act_1124340806289175`）
- **原価 = Shopify** の variant `inventoryItem.unitCost`。**送料込み**（送料無料運営のため追加送料計算は不要）
- ROASはMeta表示値を信用せず、必ず **購入価値÷消化額** を自分で割り算する（同名キャンペーン合算時にMetaのROAS列が約2倍になるバグを確認済み）
- 決済手数料 約3.4% は全体サマリーでのみ言及（商品別テーブルには含めない）

## 手順

### 1. Shopify売上（4期間、必ず「昨日」を終端にする）
`mcp__Shopify__run-analytics-query` で以下を期間別に4回:
```
FROM sales SHOW net_sales, net_items_sold GROUP BY product_title ORDER BY net_sales DESC SINCE <開始日> UNTIL <昨日> LIMIT 35
```
期間: 前日（昨日のみ）/ 直近3日 / 直近7日 / 直近30日

### 2. Meta広告費（日別×キャンペーン別）
`data_query` (ds_id=FA, ds_accounts=act_1124340806289175, timezone=Asia/Tokyo):
```
fields: date,adcampaign_name,cost,offsite_conversions_fb_pixel_purchase,offsite_conversion_value_fb_pixel_purchase
直近30日 (date_range_type=custom, 昨日終端)
```
→ `get_async_query_results` で取得し、4期間に自分で集計する。

### 4. 商品⇄キャンペーン対応（確定済みマッピング）
基本は名前の部分一致で1:1。**類似名の混同に注意**:
- Meta「ディスペンサー」= Shopify「壁掛けディスペンサー」（広告文で確認済み。オートソープディスペンサーではない）
- 日傘2商品（形状記憶／完全遮光…UV日傘）は**同一SKUの重複出品**。個別の突合は歪むので、突合チェック時は「日傘グループ」で合算してよい
- シェーバー2種（携帯電動／ムダ毛）、ファン系（4WAY／旧・瞬間冷却／3WAY／卓上）も相互流入があるためグループでのサニティチェック可
- 「カタログ全部（テスト）」は全商品横断のカタログ広告 → **広告費はどの商品にも配賦せず、全体サマリーで差し引く**

### 5. 計算
各商品×各期間で:
- 原価合計 = 販売数 × 単価原価
- **利益 = Shopify純売上 − 原価合計 − Meta広告費**
- 利益率 = 利益 ÷ 純売上、MER = 純売上 ÷ 広告費
計算はPythonスクリプトで行う（暗算しない）。

### 6. 突合サニティチェック（毎回実施）
商品ごとに Meta計上売上 ÷ Shopify純売上 を出す。**90〜105%が正常帯**。
- 100%超は異常ではない: ①Metaはカート全体の金額をクリック商品に計上する ②Shopify純売上は値引き後でMetaは値引き前 ③類似商品間の相互流入 が原因
- **110%超 or 70%未満が続く場合のみ**フラグを立てる（ピクセル二重発火・マッピングずれ・カタログとの重複計上を疑う）

### 7. 判定ルール（期間の役割分担）
- **前日**: 監視のみ。消化急増・購入ゼロの異常検知。単日で意思決定しない
- **3日**: 悪化の連続性確認（3日連続赤字→翌週の要注意リスト入り）
- **7日**: **意思決定の基本単位**
  - 7日利益がマイナス → テコ入れ案（CTR低=クリエイティブ / CVR低=LP・オファー / CPM高=ターゲット拡張）を出し、2週連続マイナスなら停止提案
  - 7日MERが損益分岐(=純売上単価÷(単価−原価)で商品別に算出)を大きく超え30日も安定 → +20〜30%の増額提案
- **30日**: 戦略判断（商品の育成/撤退、季節性）。新商品は購入50件たまるまで確定判断しない
- 季節性メモ: 主力の大半が夏物（日傘・冷感・ファン・UV・虫よけ）。8月後半以降の失速を前提に、秋主力候補（ネックマッサージャー、姿勢サポート系、ジェットウォッシャー等）のテスト状況を毎回確認する

### 8. 出力フォーマット（日本語・簡潔に）
1. **冒頭: 前回からの変化点・アラート**（新たな赤字転落、急落/急伸、突合異常）
2. 全体サマリー（4期間の 売上/広告費/利益、カタログ広告費差引後）
3. 商品別テーブル（4期間の利益、7日MER、判定: 🚀増額/✅維持/🔧テコ入れ/🚨赤字）
4. 推奨アクション（優先順・根拠つき、3〜5個まで）
