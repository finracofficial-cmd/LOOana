1. コンビニ払いを足す（KOMOJU）
════════════════════════════════════════

所要 30分（審査待ちが入る場合あり）／ 追加費用: 決済手数料のみ ／ ページ重量 ±0

▼ 手順

  ① KOMOJUの管理画面（komoju.com）にログイン
     設定 → 決済手段 → 「コンビニ決済（Konbini）」を有効にする
     ※ 事業者情報の追加提出を求められることがある。ここが待ち時間になる

  ② Shopify管理画面 → 設定 → 決済 → 「追加の決済方法」
     KOMOJU は決済手段ごとに別々の行として並ぶ。
     「KOMOJU - コンビニ (Konbini)」を有効化する。
     見当たらない場合は①がまだ反映されていない。数分待って再読み込み。

  ③ 設定 → 決済 の画面で、決済手段の並び順を確認する。
     カード → PayPay/メルペイ → コンビニ → Paidy の順が無難。
     上から3つは1画面に収まるので、コンビニを4番目に置くと意味が薄れる。

  ④ 自分のスマホで実際に1件テスト購入する。
     コンビニを選ぶ → 払込票番号が出る → そのまま放置。
     Shopifyの注文一覧に「支払い保留」で入ることを確認する。

▼ まず用語の整理（ここを取り違えると判断を間違える）

  コンビニ払い・銀行振込・ペイジーは **前払い（先払い）** です。後払いではない。
  客は注文したあと、自分でコンビニなり銀行なりに行って払う。
  つまり「注文は立っているが、まだ1円も入っていない」状態が数日続く。

  後払いなのは Paidy のほうで、これは既に入れています。
  Paidy は Paidy 社が与信を取って立て替えるので、こちらに未回収リスクはない。

  なので気にすべきリスクは「客が受け取ったのに払わない」ではなく、
  **「入金される前に発送してしまう」** ほうです。ご懸念のとおり、これは実在します。

▼ Shopify本体の挙動（公式に確認済み）

  KOMOJUのような追加の決済プロバイダで支払いが保留のとき、
  注文の支払いステータスは「支払い保留（Payment pending）」になり、
  **Shopifyは支払い保留の注文を自動フルフィルメントしません。**
  Shopifyのヘルプにも「フルフィルメントは禁止されないが、確実に代金を受け取るため
  ステータスが『支払い済み』になるまで待つこと」と明記されています。

  また支払い保留の間は、注文の編集・キャンセルがブロックされます。
  （出典: Shopify Help Center "Pending payments from additional providers"）

  → Shopifyの標準設定のままなら、勝手に発送されることはない。

▼ 穴はここ ── CJのアプリ

  危ないのは Shopify ではなく、注文を取りに来る **CJ Dropshipping のアプリ側** です。
  CJのアプリには自動発注（Auto Order / Auto Payment）の設定があり、
  ここが「新規注文をすべて取り込む」になっていると、
  Shopify が支払い保留にしていても CJ 側が先に発注してしまいます。

  コンビニ払いを有効にする前に、この順番で確認してください。

  ① Shopify管理画面 → 設定 → チェックアウト → 「注文の処理」
     自動フルフィルメントの設定を確認する。
     「支払い済みの注文のみ」以外になっていたら直す。

  ② CJのアプリを開く → Settings（設定）→ Auto Order / 自動発注
     取り込み対象が「Paid（支払い済み）の注文のみ」になっているか確認する。
     ここが最重要。**この1項目だけは、有効化の前に必ず自分の目で見てください。**

  ③ 有効化したあと、自分でコンビニ払いのテスト注文を1件入れて放置する。
     30分後にCJ側に発注が飛んでいないことを確認する。
     飛んでいたら即コンビニ払いをOFFにして、②を直してからやり直す。

  この③のテストをやるまでは、コンビニ払いを本番で開けないでください。
  1件でも未入金発送が出ると、商品代も送料も丸損になります。

▼ 未入金のまま期限切れになったら

  KOMOJU側で支払い期限（通常3〜7日）が切れると、その注文はキャンセル扱いになります。
  銀行振込は特に未入金率が高いので、KOMOJUの管理画面で
  支払い期限とリマインドメールを設定しておいてください。

  最初はコンビニ払いだけにして、銀行振込は入れないことをお勧めします。
  コンビニは払込票を持って店に行けば終わりですが、銀行振込は
  平日日中にATMか振込操作が要るぶん、未入金で流れる率が明確に高い。

▼ 日次レポートへの影響（これは私の側の作業）

  Shopifyの売上レポートは「入金」ではなく「注文」で計上する。
  コンビニ払いを入れると、未入金の注文が gross_sales に混ざる。
  つまり MER が実際より良く出る。

  対応: コンビニ払いを有効にした日から、日次レポートに
        「未入金（支払い保留）の注文件数と金額」を1行足す。
        MERは従来どおり注文ベースで出し、その横に未入金額を併記する。
        有効化した日を教えてください。その日からレポートを変えます。

▼ 判定

  実施+7日で レジ完了率（購入完了 ÷ レジ到達）を 48.98% と比べる。
  同時にコンビニ払いの利用件数を見る。
  利用が全注文の3%未満なら効果なしと判断して、それ以上は追わない。

2. カゴ落ちメールを1通 → 3通にする
════════════════════════════════════════

所要 1時間 ／ 追加費用 0円（Shopify Emailの無料枠 月10,000通に余裕で収まる）
／ ページ重量 ±0

まず正確なところ。Shopify標準のカゴ落ちメールは1通しか送れない。
3通にするには Shopify Email のオートメーションを使う。両方ONにすると
二重送信になるので、標準を止めてオートメーションに寄せる。

▼ 手順

  ① いまの状態を確認する
     設定 → チェックアウト → 「放棄したチェックアウト」
     自動送信がONか、何時間後になっているかをメモする。

  ② 文面を確認する
     設定 → 通知 → 「放棄したチェックアウト」
     いまの文面を全部コピーしてどこかに保存しておく（③で使う）。

  ③ オートメーションを作る
     マーケティング → オートメーション → 「オートメーションを作成」
     テンプレート一覧から「放棄したチェックアウト」を選ぶ

     待機時間とメールを3段に組む:
       1通目  1時間後
       2通目  24時間後
       3通目  72時間後

  ④ ①の標準送信をOFFにする
     ③が動き出すのを確認してから切る。順番を逆にすると空白期間ができる。

  ⑤ 自分でカゴ落ちを1件作ってテストする
     レジでメールアドレスまで入れて離脱 → 1時間後に届くか確認。

▼ 3通の文面（そのまま使えます）

  ─── 1通目（1時間後）件名: カートに商品が残っています ───

  先ほどご覧いただいた商品を、カートにお取り置きしています。

  ご注文手続きの途中でお困りのことはありませんでしたか。
  よくいただくご質問をまとめました。

  ・送料は全国どこでも無料です。追加の費用はかかりません。
  ・お支払いはクレジットカード、PayPay、メルペイ、あと払い（Paidy）
    からお選びいただけます。
  ・商品が届いてからのご返品も承っています。

  カートはこちら
  ［カートへ戻るボタン］

  ─── 2通目（24時間後）件名: ご注文手続きは途中のままです ───

  昨日カートに入れていただいた商品は、まだお取り置きしています。

  迷われている理由がもし「本当に自分に合うか分からない」であれば、
  実際にお使いいただいた方の声を読んでみてください。

  ［商品ページのレビューへのリンク］

  サイズや使い方でご不明な点があれば、このメールにそのまま
  ご返信ください。担当者がお答えします。

  ［カートへ戻るボタン］

  ─── 3通目（72時間後）件名: カートのお取り置きについて ───

  カートにお取り置きしている商品について、最後のご案内です。

  在庫の状況によっては、次回入荷までお時間をいただく場合があります。
  お求めをお考えでしたら、このタイミングでご確認ください。

  ［カートへ戻るボタン］

  ご不要でしたら、このメールは破棄していただいて大丈夫です。

▼ 書くときの注意

  ・割引クーポンを入れない。
    カゴ落ちにクーポンを出すと「待てば安くなる」を学習されて、
    通常購入までクーポン待ちになる。粗利も直接削る。
    まずクーポンなしで回収率を測る。効かなかったら次に考える。

  ・「残りわずか」「在庫が少なくなっています」と書かない。
    実際に在庫を持っていないので、これは事実と違う。
    3通目の書き方は「入荷までお時間をいただく場合があります」に留めてある。

▼ 判定

  実施+7日で以下2つ。
    ・流入元 email のセッション数（現在 7日で58）
    ・放棄カゴ件数（現在 7日で263）に対する回収注文数

  回収率10%なら 利益 +95,184円/7日、月+407,931円。
  5%でも 月+203,966円。

3. 楽天ペイ・d払い・au PAY を足す（KOMOJU）
════════════════════════════════════════

⚠️ 訂正: 前の資料に「Amazon Pay」と書きましたが、**使えません。**
   ShopifyはAmazon Payのサポートを 2025年1月6日 に終了し、
   日本のストアからは自動的に削除されています。私の誤りでした。

   代わりに、いま契約している KOMOJU にそのまま足せる決済手段があります。
   KOMOJU が Shopify 向けに提供しているのは以下です。

     クレジットカード（Visa/Master/JCB/AMEX/Diners/Discover）  ← 導入済み
     スマホ決済（PayPay / メルペイ）                          ← 導入済み
     Paidy                                                    ← 導入済み
     コンビニ決済（ローソン/ファミマ/ミニストップ/デイリー/セイコマ）  ← 手順1
     セブンイレブン（法人のみ申請可）                          ← 手順1
     銀行振込 / ペイジー                                      ← 見送り推奨
     **楽天ペイ / d払い / au PAY**                            ← ここ
     電子マネー（WebMoney / BitCash / NetCash）

   楽天ペイは日本で利用者が多く、Amazon Payの代わりとして一番近い。
   しかも新しい契約先を増やさずに済みます。

所要 30分＋審査 ／ 追加費用: 決済手数料 ／ ページ重量 ±0

▼ 手順

  ① KOMOJUの管理画面 → 設定 → 決済手段
     「楽天ペイ」「d払い」「au PAY」を有効にする。
     決済手段ごとに審査が入ります。楽天ペイは特に時間がかかることがある。

  ② Shopify管理画面 → 設定 → 決済 → 「追加の決済方法」
     承認された手段が行として増えるので、有効化する。

  ③ 決済手段の並び順を整える。
     カード → PayPay/メルペイ → 楽天ペイ → コンビニ → Paidy → d払い/au PAY

  ④ 自分で1件ずつテスト購入する。

  ※ これらは前払いでも後払いでもなく、その場で決済が完了します。
    手順1のような未入金発送のリスクはありません。

▼ 手数料の心配について

  外部決済なので Shopify の外部決済手数料 0.6% が乗ります。
  KOMOJU側の料率は決済手段ごとに違うので、有効化前に管理画面で確認してください。

  ただし金額で見ると、この心配はほぼ意味がない。

    新決済のシェア   手数料の上乗せ   必要な追加注文   必要なレジ完了率
        10%            1.25%          +1.9件         49.07%
        20%            1.25%          +3.8件         49.16%
        30%            2.00%          +9.0件         49.41%

  現在のレジ完了率は 48.98%。
  どのケースも「完了率が0.5pt上がれば手数料の上乗せは全部回収できる」。
  参考までに、完了率を1か月前の51.6%に戻すと利益は +198,598円/7日。
  手数料の差はこの額の前ではノイズ。

▼ 判定

  実施+7日で レジ完了率。あわせて各決済手段の利用シェアを見る。
  シェアが全注文の3%未満の手段は、手数料だけ払って効果ゼロなので外す。

4. 加速チェックアウトボタン（Shop Pay / Apple Pay / Google Pay）
════════════════════════════════════════

所要 15分 ／ 追加費用 0円 ／ ページ重量 ±0

これは「連絡先を入れる前に消える808人」に直接効く唯一の打ち手。
レジのフォームを丸ごと飛ばせる。

▼ 手順

  ① ウォレットを有効にする
     設定 → 決済 → Shopify Payments の「管理」
     ウォレット の欄で Shop Pay / Apple Pay / Google Pay にチェック

  ② 商品ページにボタンを出す
     オンラインストア → テーマ → カスタマイズ
     商品ページを開く → 「商品情報」セクション → 「購入ボタン」ブロック
     「動的チェックアウトボタンを表示する」にチェック → 保存

     ※ 商品テンプレートが38個ある。ここが面倒なところ。
       全部に入れたい場合は下の「一括でやる場合」を見てください。

  ③ カートページにボタンを出す
     カスタマイズ → カート → 「カート」セクション
     加速チェックアウトボタンの表示をON

▼ 一括でやる場合

  関連商品セクションのときと同じで、Shopify CLI でテンプレートを
  引っ張ってきて一括編集するのが早い。手順は
  data/theme-ops/enable-related-2026-08-14.md と同じ流れ。
  必要ならスクリプトを書きます（`show_dynamic_checkout` の設定を
  全 product*.json で true にするだけ）。

▼ ⚠️ 副作用（これが理由で優先度を4番目にしている）

  加速チェックアウトはカートページを飛ばす。つまり
    ・Selleasy のカートアップセル
    ・優先配送（現在のアタッチ率 2.39%）
  を素通りする。

  優先配送は原価0なので、売上がそのまま利益になる商品です。
  ここが削れると、レジ完了率が上がっても差し引きマイナスになりうる。

  だから実施後7日は、必ずこの2つを並べて見る。
    ・レジ完了率（現在 48.98%）
    ・優先配送のアタッチ率（現在 2.39%）
  完了率の伸びより優先配送の落ち幅が大きければ、元に戻す。

  先に商品ページのボタンだけ入れて、カートページは後にする手もある。
  商品ページからの加速チェックアウトはもともとカートを通らないので、
  アップセルの取りこぼしが増えない。まずこちらだけ試すのが安全です。

5. LINE のカゴ落ち通知
════════════════════════════════════════

所要 半日〜1日 ／ 追加費用: アプリ月額＋LINEのメッセージ配信料 ／ ページ重量 小

日本のECはメール開封率が低い。LINEは桁が違う。
ただし2（メール3通）を先にやってください。無料で効果が測れるので、
そこでの回収率を見てからLINEに金を払うかを決めたほうがいい。

▼ 手順

  ① LINE公式アカウントを作る
     LINE for Business から開設。無料プランで始められる。
     無料プランはメッセージ200通/月まで。カゴ落ちが月1,100件前後
     あるので、動かすなら有料プラン（ライト/スタンダード）が要る。

  ② Shopifyアプリを入れる
     候補: CRM PLUS on LINE（国産・Shopify連携が正式・日本語サポート）
           Social PLUS
     どちらも月額。金額はプランで変わるので申込前に確認してください。

  ③ 友だち追加の導線を置く
     ・注文完了ページ（設定 → チェックアウト → 注文状況ページの追加スクリプト）
     ・注文確認メール（設定 → 通知 → 注文確認）
     ここで友だちを貯めないと、カゴ落ちLINEを送る相手がいない。
     ここが一番の律速。効果が出るまで1〜2か月かかります。

  ④ カゴ落ちシナリオを組む
     文面は2の3通をそのまま短くして使えます。
     LINEは長文が読まれないので、1通あたり3行以内に。

▼ 判定

  友だち数の増え方をまず見る（1か月で何人貯まるか）。
  貯まってから初めて回収率を測る。
  友だちが月200人未満しか貯まらないなら、アプリ代のほうが高い。
  そのときは解約してメールに戻す。

6. 偽の緊急性を外す
════════════════════════════════════════

所要 1時間 ／ 追加費用 0円 ／ ページ重量 減る

公開されているページを実際に読んで、中身を確認しました。
2つあります。**片方は完全に壊れています。**

──────────────────────────
6-A 偽のカウントダウンタイマー（これは今すぐ消していい）
──────────────────────────

  場所: snippets/price.liquid（価格の表示部分）
  中身:

    let duration = 20 * 60;   // 20分
    ...
    document.getElementById("minutes").textContent = ...
    if (timer < 0) { timer = duration; }   // 0になったら復活

  20分で無限にループするタイマーです。
  ただし **#minutes と #seconds という要素がページ上に存在しません。**
  実測: 商品ページ・コレクションページのどちらにも0個。

  つまりこのタイマーは画面に何も表示していない。
  そのかわり、1秒ごとに JavaScript のエラーを投げ続けています。

  しかも price.liquid にあるので、商品カード1枚につき1つ動く。
  コレクションページ（/collections/all）を実測したところ、
  **同じタイマーが16個、同時に走っていました。**

  → 表示しているものが何も無いので、消してもCVRは1ミリも下がりません。
    純粋に軽くなるだけ。最初にこれをやってください。

  やり方:
    オンラインストア → テーマ → 「…」→ コードを編集
    左の検索窓に price.liquid と入れて開く
    `20 * 60` で検索して、その <script> ... </script> を丸ごと削除
    保存

    同じファイルにある

      <div class="low-stock-text">
        <span class="dot"></span>
        残りわずか お早めに
      </div>

    も一緒に消してください。在庫を持っていないので、これは事実ではない。
    こちらは表示されているのでCVRが少し下がる可能性はありますが、
    全商品カードに常時出ている「残りわずか」は、もう誰も信じていません。

    ※ 消す前に、そのファイルの中身を全部コピーしてどこかに保存しておいてください。
      テーマのコード編集には元に戻すボタンがありません。

──────────────────────────
6-B 偽の「今〇人がカートに追加しています。」
──────────────────────────

  場所: 商品テンプレート（templates/product*.json）の custom_liquid ブロック
  中身:

    document.getElementById("liveCount").innerText =
      Math.floor(Math.random() * 5) + 2;

  ページを開くたびに 2〜6 の乱数を出しているだけです。
  在庫とも閲覧者数とも一切連動していません。

  これは38個のテンプレート全部に入っているので、
  テーマエディタで1つずつ消すのは現実的ではない。
  スクリプトを書きました。

    scripts/theme/remove-live-view.mjs

  使い方（関連商品セクションのときと同じ流れです）:

    shopify theme pull --store h8ct0k-r2.myshopify.com --theme 159681577202 --only 'templates/product*.json'
    node remove-live-view.mjs --dry-run      ← まず何件当たるか見る（書き込まない）
    node remove-live-view.mjs
    shopify theme push --store h8ct0k-r2.myshopify.com --theme 159681577202 --only 'templates/product*.json'

  戻すとき:
    node remove-live-view.mjs --restore
    そのあともう一度 push

  安全性はダミーで検証済みです。
    ・liveCount を含む custom_liquid ブロックだけを外す
    ・送料表記など他の custom_liquid は触らない
    ・関連商品セクションの設定も触らない
    ・2回流しても2回目は何もしない（冪等）
    ・--restore でバックアップと1バイトも違わない状態に戻る
